# OpenSpec Change - 添加只读 DeFi 跨 DEX 套利机会扫描器

## Change ID: `change_add_readonly_defi_arbitrage_scanner`
## 状态: Draft（待范围与技术选型确认；尚未实施）
## 目标模块: `defi-arbitrage`

> 本仓库沿用 `spec/change_*.md` 平铺格式。本文集中承载 proposal、design、tasks、业务上下文、需求增量和风险检查，不初始化新的 OpenSpec 工程。本次仅编写 change，不表示已经批准实现、配置在线服务或执行交易。

## 1. 变更背景与目标

### 1.1 Why：现有系统与套利目标的差距

目前系统主要从新闻、热度、技术指标、TVL 和链上买卖笔数中发现方向交易线索。它没有验证指定投入金额经过多次兑换后，扣除成本是否仍然盈利。

现有代码依据（路径相对于 `projects/binance-square-scanner/`）：

| 代码 | 当前职责 | 本 change 的处理 |
|---|---|---|
| `bsc/monitors/onchain.py` 的 `compute_pair_signal` | 计算强买盘分数 | 不修改评分，也不把分数作为套利准入条件 |
| `bsc/monitors/onchain.py` 的 `build_monitor_payload` | 每次搜索保留一个 `best_pair` | 新模块独立保留同一资产的多个白名单池，不改变旧榜单行为 |
| `bsc/monitors/meme_early.py` | 候选发现、安全信息和多池流动性结构观察 | 聚合行情只能辅助发现，不作为链上执行报价 |
| `bsc/trading/instrument_mapper.py` | Binance 标的映射，并拒绝链上资产 | 保留拒绝逻辑，不将链上代币拼接为 CEX 交易对 |
| `bsc/trading/paper.py` | 固定滑点与费用假设下的方向纸交易 | 不用它验证 DEX 多步兑换，也不复用其资金费率模型 |
| `bsc/trading/store.py`、`bsc/notifications/webhook.py` | SQLite 审计和通知 | 参考幂等、审计模式；通知可复用，套利数据使用独立库 |

这些引用是跨模块依赖，标记为 **Needs review**：实施前核对接口，不能顺带修改已有模块。当前仓库没有 `.agent/business-logic/defi-arbitrage/`，不虚构业务上下文文件。

### 1.2 Goals：最小可验证闭环

**在一条链的两个指定 DEX 之间，发现同一资产的两跳闭环兑换机会，输出可复核的报价、模拟证据和预计净利润；不签名、不下单。**

```text
白名单资产与池
  -> 固定区块的池状态与分档报价
  -> A -> B -> A 的两跳路径
  -> 完整路径只读模拟
  -> 全成本核算与准入判断
  -> 独立存储、报告、可选提醒
  -> 历史快照回放与延迟敏感性评估
```

验收关注计算正确、证据完整、异常拒绝、结果可复现，不要求一定发现盈利机会，也不承诺收益。

### 1.3 Non-goals：V1 不做

- 钱包连接、私钥或助记词接入、签名、广播、真实账户授权、公共链合约部署。
- 闪电贷、三角套利、任意多跳路径搜索、跨链或跨 CEX/DEX 套利。
- 现货/永续对冲、资金费率套利、借贷利差和清算策略。
- Mempool 监听、抢跑、夹子交易、私有交易提交或其他 MEV 执行能力。
- 追踪别人已经完成的套利交易、搜索者地址画像或历史交易利润归因。
- 全网新币扫描、通用 DEX 插件框架、新闻评分重构、Web UI、外部消息中间件。
- 修复 Hyperliquid 负费率分类、改造旧纸交易资金费率计算等独立问题。

## 2. 实施前决策与审批门槛

本草案暂以 **EVM 链、普通 ERC-20 资产、两个指定 DEX 版本**为技术假设，不默认选择任何链、协议、池地址或服务供应商。若目标是非 EVM 链，先修订本 change，不直接套用 EVM 设计。

| 门槛 | 必须确认的内容 | 未确认时的行为 |
|---|---|---|
| G1：市场范围 | 唯一 `chain_id`；两个 DEX 的版本、池类型、可信 factory/router/quoter；结算资产 A、交易资产 B 及池白名单 | 只保留草案，不开始绑定协议的实现 |
| G2：数据与模拟 | 只读 RPC、历史状态能力、完整路径模拟后端；目标链全部执行费用的估算方式；Gas 计价转换来源 | 不得以两个独立报价代替完整模拟，不能宣称扫描器已验收 |
| G3：参数与预算 | 输入金额档位、最大扫描池数、请求预算、超时、区块/时间过期门槛、净利润门槛、风险缓冲、通知冷却 | 不自动替用户选择资金规模或采购付费服务 |
| G4：实施批准 | 用户确认 G1-G3 及本文范围 | 才可开始实现；批准本 change 不授权任何实盘操作 |

默认不启用外部 Webhook。需要在线 RPC 或通知时，由运行者显式配置；凭据不写入文档、样例、数据库或报告。

## 4. 核心数据契约

### 4.1 身份与数值

- 资产唯一键为 `chain_id + token_address`，symbol 只用于展示；地址按目标链规则校验和规范化。
- 池必须属于确认的 factory/协议版本，链上 `token0/token1`、decimals、费率须与配置一致；仅有聚合网站的 DEX 标签不足以证明身份。
- 路径只允许同链、相同 A/B 地址、两个不同池且属于两个指定 DEX 的 `A -> B -> A`；同时枚举反向的池顺序。
- 数量计算使用最小单位整数；序列化为十进制字符串。估值换算使用 `Decimal` 或等价精确运算，禁止二进制浮点决定收益正负。
- V1 不支持转账税、rebasing、动态费用或额外 hook 等未经适配确认的行为；不能确认兼容性的资产/池直接拒绝，不猜测。
- 不按币名合并资产，不默认 USDC/USDT 等价，不把不同包装或桥接资产视为可无成本互换。

### 4.2 `ArbitrageObservationV1`

| 字段组 | 最小字段 |
|---|---|
| 版本与关联 | `schema_version`、`strategy_version`、`config_digest`、`route_id`、`observation_id`、`trace_id` |
| 资产与路径 | `chain_id`、结算资产地址与 decimals、两腿完整资产/池/方向/协议版本 |
| 区块与时间 | `block_number`、`block_hash`、`block_timestamp`、`received_at`、`quoted_at`、`simulated_at`、`expires_at` |
| 报价 | `amount_in_atomic`、每腿输入/输出、`quoted_amount_out_atomic`、报价来源与费率 |
| 模拟证据 | `simulation_status`、后端与版本、调用数据摘要、模拟账户前提、各腿结果、`simulated_amount_out_atomic`、失败原因、原始证据引用 |
| 成本 | Gas 数量与价格上界、目标链其他必需费用、转换来源及时间、`chain_cost_atomic`、`other_cost_atomic`、`cost_status` |
| 判断 | `net_profit_atomic`、`net_profit_bps`、`safety_buffer_atomic`、`decision`、`reason_codes` |
| 提醒与研究 | 提醒状态、同路径后续观察引用、回放来源 |

所有时间使用 UTC；缺失值必须是明确的 `null` 或失败状态，不能用零掩盖。生成报告时不能刷新原始报价时间来延长有效期。

`route_id` 由链、完整资产路径、池与方向确定，不含扫描时间。`observation_id` 由策略版本、配置摘要、区块哈希、路径、投入金额和估算假设版本确定；同一语义重复处理不生成新观察，参数或区块改变必须产生独立观察。

## 5. 报价、模拟与收益判断

### 5.1 池来源与扫描调度

V1 直接使用经核验的显式池白名单，不依赖 DexScreener 搜索才能启动。现有聚合数据可以人工辅助选池，但不能自动扩大白名单，不能把 `priceUsd` 用作可成交报价。

第一版采用受请求预算约束的区块头轮询：发现新区块后，对有限白名单重新扫描；不实现全网事件索引和任意路径图搜索。所有 RPC 设置超时及有限重试，区分“没有机会”和“数据源不可用”。

### 5.2 同一区块报价

1. 先取得区块 B 的编号、哈希和时间，再读取资产、池状态及指定金额的报价。
2. 所有报价固定在 B，不在中途混入 `latest`。RPC 不支持哈希定位时，使用明确编号并在读取前后核对哈希。
3. 第一腿的实际报价输出作为第二腿输入，按已确认的池类型与费率计算；不得使用固定百分比滑点替代池曲线。
4. 每个投入档位独立计算，不将最小档位利润线性放大；以净利润和容量形成报告，不使用新闻热度或买盘分数排序。
5. 报价结束、模拟结束以及通知前重新检查区块 canonical 状态和新鲜度；来源不同块或不能证明一致时拒绝。

两腿报价只是初筛证据。即使报价闭环为正，仍须进入完整路径模拟，不能直接形成“模拟盈利”提醒。

### 5.3 完整路径只读模拟

- G2 必须选择能够在固定 B 状态下顺序执行完整两腿的后端，并保留调用结果、资产余额变化、revert 信息与 Gas 证据。
- 模拟的是完整路径调用，不能把两次互相隔离的 `eth_call` 或 Quoter 输出相加，冒充一次原子执行。
- 可以使用隔离本地分叉或受支持的调用状态覆盖；资金与授权仅在模拟上下文中设置，必须记录这些前提，不表示真实账户具备资金或授权。
- 不允许为得到盈利结果而修改池储备、费率、代币代码或其他市场状态；只允许为模拟账户提供声明的输入资金及必要授权。
- 如需模拟调用工件，只在隔离上下文使用，不部署公共链；模拟路径必须与报价路径、协议版本和金额一致。
- 必须校验余额变化与交换事件/返回值一致；任意一腿失败、金额不一致、证据不完整时不能通过。
- 无可用模拟后端时，诊断输出最多标记为 `quoted_only`，不得进入盈利提醒，也不算完成 G2 或 V1 验收。

### 5.4 成本与净利润

统一用起始/最终资产 A 的最小单位计算：

```text
net_profit_atomic
  = simulated_amount_out_atomic
  - amount_in_atomic
  - chain_cost_atomic
  - other_cost_atomic

net_profit_bps = net_profit_atomic * 10000 / amount_in_atomic
```

- 兑换输出中已计入的池手续费和价格影响不重复扣除；它们可以展示为明细，但必须标注“已包含”。
- `chain_cost_atomic` 覆盖完整模拟路径的执行 Gas，以及目标链要求的其他费用；若是 L2，不能默认数据费等额外成本为零。
- Gas 价格上界、费用模型和原生币到 A 的换算来源必须留痕并满足时效规则；换算成本向上取整。不默认稳定币等于一美元，不以缺失价格作零成本。
- 需要前置授权等操作时，其成本或已完成前提必须披露；未明确的必要成本视为 `cost_incomplete`，不能自动忽略。
- 本版不使用闪电贷或外部执行提交，不能用虚构的零手续费贷款或零成本补贴改善结果。
- 风险缓冲是准入要求，不冒充已发生费用。仅当净利润为正、达到绝对值与 bps 门槛且覆盖 `safety_buffer_atomic` 时，才满足盈利准入；不能仅按四舍五入后的展示值判断。
- 报告统一称“该区块与模拟假设下的预计净利润”，不称实际收益、稳赚或可保证成交利润。

### 5.5 决策与有效性

| `decision` | 含义 | 可否发送盈利提醒 |
|---|---|---|
| `quoted_only` | 只有报价，未获得完整模拟与成本证据 | 否 |
| `simulated_profitable` | 模拟通过、成本完整、通过利润和风险缓冲门槛且仍有效 | 是，且须显式配置通知 |
| `simulated_unprofitable` | 模拟完成但未达到盈利准入门槛 | 否 |
| `rejected` | 身份、数据、模拟或必要成本校验失败 | 否 |
| `expired` | 区块落后或超过时间有效期 | 否 |
| `invalidated_reorg` | 原报价区块不再属于 canonical 链 | 否 |

至少提供 `chain_mismatch`、`asset_mismatch`、`unsupported_pool`、`unsupported_token`、`block_mismatch`、`rpc_unavailable`、`simulation_unavailable`、`simulation_reverted`、`cost_incomplete`、`profit_below_threshold`、`quote_expired`、`block_reorg` 等可枚举原因。

已盈利观察也会过期或因重组失效，状态变化追加审计而非抹去原始证据。重试必须保留原区块和原始采集时间；改用新区块应生成新观察，不能为旧结果续期。

## 6. 存储、提醒与回放

### 6.1 Data / Audit impact

- 默认独立使用 `results/defi_arbitrage.sqlite3`，保存配置摘要、报价与模拟证据、观察决定、状态历史及提醒尝试。
- 原始 RPC 请求仅保存脱敏的方法、参数摘要和关联信息，不保存带凭据的 URL、Header 或敏感响应内容。
- 同一路径、同一区块、相同金额与版本的重复扫描最多产生一条观察；无利润与失败结果也要保存，以计算真实拒绝率。
- 持久化失败时不得发送盈利提醒；不能先通知成功再尝试记录关键证据。
- 数据源中断时禁止继续把历史结果显示为当前有效机会；恢复后重新扫描新区块。

### 6.2 可选提醒

复用 `bsc/notifications/webhook.py` 时，传入稳定 `alert_id` 并保存每次尝试。冷却按路径及金额档位计算，不能因为每块都有新 ID 而绕过冷却；阈值、重大变化条件与失效通知规则在 G3 确认。

超时后用同一个 `alert_id` 重试；外部通知按至少一次投递设计，不宣称接收方一定恰好收到一次。未配置 Webhook 时仅输出本地 JSON/Markdown 报告；重放默认绝不发送外部消息。

### 6.3 离线回放与观察指标

- 回放样例包括池/资产身份、区块编号与哈希、原始报价、完整模拟证据、费用来源、配置版本和后续快照；禁止联网补齐缺失字段。
- 同一输入和版本应得到相同的观察 ID、成本与决策。离线夹具只验证确定性，不代替真实协议适配和完整路径模拟验收。
- 下一块或指定延迟后的结果作为后续标签保存，不能反向参与最初时刻的筛选；缺少历史状态或模拟证据时标为不可评估，不能编造收益。
- 记录报价候选数、模拟通过率、成本拒绝率、过期率、净利润与容量分布、机会持续区块数和端到端延迟。
- 不把不同档位、相互重叠机会或连续区块的预计利润直接相加成“日收益”；同一资金和竞争路径不能重复占用。

## 7. Permission impact 与风险检查清单

本 change 不增加交易权限。公共 RPC 只允许明确列出的读取与模拟方法；实现中不得包含交易签名器、发送交易方法、真实账户授权或外部实盘脚本调用。隔离模拟环境的状态准备不得指向公共 RPC。

实施和上线观察前逐项审查：

- [ ] 已批准 G1-G4，地址和协议版本来自可信来源，不使用搜索结果中的同名资产代替。
- [ ] 没有私钥、助记词、签名、广播、公共链部署或真实授权路径；未知/实盘参数明确拒绝。
- [ ] 所有必要池状态、报价和完整模拟可关联到同一区块哈希，不通过修改模拟市场状态制造利润。
- [ ] 所有金额使用正确精度，完整链费用和换算来源齐全，不重复扣费，也不把缺失成本记成零。
- [ ] 税币、不支持池、报价过期、RPC 失败、重组和模拟失败均为 fail-closed。
- [ ] 外部服务使用有界超时、重试与请求预算；凭据和带密钥的 endpoint 已脱敏。
- [ ] 提醒具备冷却、稳定幂等标识和有效性复检，离线回放不联网、不推送。

## 9. ADDED Requirements（需求增量与验收场景）

### Requirement: R1 - 身份明确且范围受限

系统 MUST 只处理已确认链、资产地址和协议池，MUST NOT 仅凭 symbol 或展示价格建立套利路径。

#### Scenario: 同名资产不能合并

- WHEN 两个池的币名相同但合约地址不同，或来自不同链。
- THEN 拒绝组成路径，记录身份不匹配原因；不得出现盈利提醒。

#### Scenario: 两种池顺序与金额精度

- WHEN 白名单 A/B 有两个合法不同 DEX 池，A 为 6 位精度、B 为 18 位精度。
- THEN 对两个池顺序和全部批准档位分别计算，第二腿输入严格等于第一腿输出的最小单位整数；结果不经浮点近似。

### Requirement: R2 - 报价与完整模拟属于同一区块

系统 MUST 保存报价和模拟的共同区块证据，MUST NOT 把独立报价拼成“完整模拟成功”。

#### Scenario: 混块或任意一腿失败

- WHEN 两腿读取来自不同区块、发生模拟 revert，或只有独立 Quoter 输出。
- THEN 分别记录 `block_mismatch`、`simulation_reverted` 或 `quoted_only`，不得进入盈利提醒。

#### Scenario: 调用与余额证据不一致

- WHEN 完整模拟的资产、池顺序、投入金额或余额变化与观察路径不一致。
- THEN 拒绝该结果并保留证据，不允许用模拟返回的单个利润数字绕过核对。

### Requirement: R3 - 净利润包含完整且不重复的成本

系统 MUST 用完整模拟输出计算净利润，MUST 对必要成本缺失采用 fail-closed。

#### Scenario: 固定净利润计算

- GIVEN A 为 6 位精度，投入 `100000000`，模拟返回 `101200000`（已含池费和价格影响），链成本 `400000`，其他必要成本 `100000`。
- WHEN 计算利润。
- THEN 净利润恰为 `700000`，收益率为 `70 bps`；不得再扣已包含的池费。风险缓冲只参与准入判断，不改写该净利润。

#### Scenario: 毛利为正但不可通过

- WHEN 毛利为正但扣费后非正、未达到任一利润门槛，或不覆盖风险缓冲。
- THEN 返回 `simulated_unprofitable`；若缺少 Gas 换算、目标链必要费用或前置成本，则返回 `rejected / cost_incomplete`，不得按零成本放行。

### Requirement: R4 - 时效、重组和来源异常使机会失效

系统 MUST 在输出和通知前复检有效性，MUST NOT 给旧证据更新生成时间来延长有效期。

#### Scenario: 处理中发生过期或重组

- WHEN 计算期间区块超过允许落后范围、时间过期或同高度 canonical 哈希改变。
- THEN 标记 `expired` 或 `invalidated_reorg`，禁止盈利提醒并保留失效审计；后续新区块生成新观察。

#### Scenario: 关键来源不可用

- WHEN RPC/模拟服务超时或证据存储失败。
- THEN 明确报告降级或失败，不返回伪造的“无风险机会”，不发送缺少持久化证据的盈利提醒。

### Requirement: R5 - 观察和通知可追溯且幂等

系统 MUST 保存全部候选决定与证据，MUST 区分内部观察幂等和外部通知投递保证。

#### Scenario: 重复处理和重启

- WHEN 同一语义观察重复处理 10 次，中途重启进程。
- THEN 仅有一个观察身份，所有通知重试复用同一 `alert_id`；接收方未保证幂等时不得宣称恰好一次投递。

#### Scenario: 不满足通知条件

- WHEN 未配置 Webhook、处于普通重复冷却、机会已失效或当前是离线回放。
- THEN 不调用外部通知接口，仍可输出本地报告与投递抑制原因。

### Requirement: R6 - 回放可复现且没有未来数据泄漏

系统 MUST 只使用观察当时可得的快照、费用及模拟证据作决策。

#### Scenario: 禁网回放与后续标签

- WHEN 对同一固定样例重复回放，并拦截全部网络请求。
- THEN 观察 ID、成本和决定一致，既不联网也不发通知；后续区块数据只能添加评估标签，缺失样本标记不可评估。

### Requirement: R7 - 只读权限与既有行为保持不变

系统 MUST NOT 签名、广播、提交真实授权或部署公共链合约，MUST 保留现有实盘禁用与链上资产映射拒绝边界。

#### Scenario: 禁止写链与旧链路回归

- WHEN 执行正常扫描、异常重试、模拟降级或传入实盘相关参数。
- THEN RPC/后端测试证明没有交易提交调用，实盘参数非零退出；现有安全测试及新增只读测试全部通过。

## 10. Rollout / Rollback

### Rollout

1. 草案阶段：确认 G1-G4；不启动在线扫描，不要求钱包，不购买服务。
2. 开发阶段：离线夹具、mock 和成本/状态测试通过后，再进行显式启用的固定区块只读集成验证。
3. 观察阶段：先仅落地本地报告，检查错误率、延迟、模拟证据和费用完整性，再决定是否启用外部提醒。
4. 观察门槛：目标链两个 DEX 均有可复核的完整路径模拟证据；零真实交易调用；风险场景与既有测试通过。没有盈利样本不算功能失败。

### Rollback

停止独立扫描进程并关闭该模块通知配置即可回退；保留独立数据库、原始证据和配置摘要供复盘，不删除历史记录，不迁移或恢复旧交易库。本 change 不替换原 Hub、新闻评分和纸交易入口，因此回退不影响原有监控。

后续若需要资金费率套利、更多链/池类型、闪电贷或实际执行，应分别另起 change，不通过本模块隐藏开关扩大权限和策略范围。
